# Repository Guidelines

MacCV is a macOS clipboard manager: a Rust engine (`maccv-core`), a thin C ABI
(`maccv-ffi`), and a SwiftUI front end.

## Project Structure & Module Organization

| Path | Contents |
|---|---|
| `crates/maccv-core/src/` | The engine: pasteboard access, content, redaction, secure input, updater. |
| `crates/maccv-core/tests/clipboard.rs` | Live tests against a process-private pasteboard. |
| `crates/maccv-ffi/src/` | The C ABI surface — it translates, it does not decide. |
| `crates/maccv-ffi/include/maccv.h` | Generated by cbindgen. Never edit by hand. |
| `apps/mac/Sources/MacCV/` | SwiftUI app. `project.yml` is the source of truth; `MacCV.xcodeproj` is generated. |
| `Scripts/` | `build-rust.sh` (used by Xcode and CI), `publish.sh`, `changelog-notes.sh`. |
| `assets/`, `docs/` | Logo/social SVGs and the GitHub Pages site. |

Keep logic in `maccv-core`; a decision written in `maccv-ffi` usually belongs one
layer down, where it can be tested without a C caller.

## Build, Test, and Development Commands

```bash
cargo test --workspace            # run the engine tests
cargo fmt --all --check           # formatting gate
cargo clippy --workspace --all-targets -- -D warnings   # warnings are errors
cd apps/mac && xcodegen generate  # regenerate the Xcode project from project.yml
Scripts/build-rust.sh --profile release --arch universal
```

Also build the FFI and run `crates/maccv-ffi/tests/smoke.c` against
`target/release/libmaccv_ffi.a` to prove the layers connect end to end.

## Coding Style & Naming Conventions

- **Rust**: `cargo fmt` decides formatting. Public items need doc comments
  (`missing_docs` is denied) and every `unsafe` block a `// SAFETY:` comment.
  Prefer `Result` over panicking — release builds use `panic = "abort"`.
  `snake_case` files/functions, `PascalCase` types.
- **Swift**: Swift 6 with strict concurrency; keep UI state on the main actor.
  Objective-C objects must never cross threads, and C pointers must never point at
  a Swift `Data`'s transient storage — see `CRepresentationStorage`.

## Testing Guidelines

- New engine behaviour requires a test. Extend
  `crates/maccv-core/tests/clipboard.rs`, exercising the real framework against a
  process-private pasteboard (never the developer's clipboard), then clean up.
- Name tests as full sentences describing the guarantee, e.g.
  `writes_files_as_file_urls`, `change_count_is_cheap_enough_to_poll`.
- Assert documented performance claims rather than measuring by hand, and keep the
  C smoke test passing for FFI additions.

## Commit & Pull Request Guidelines

Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
`feat:`, `fix:`, `perf:`, `refactor:`, `docs:`, `test:`, `build:`, `ci:`, `chore:`,
with scopes where useful (`feat(app):`, `docs(ffi):`).

Pull requests should say what changed, why, and how to verify it, and follow
`.github/PULL_REQUEST_TEMPLATE.md`. Link issues with `Closes #N`, keep one concern
per PR, and add a `CHANGELOG.md` entry under `[Unreleased]` for user-visible
changes — release notes are generated from that file.
