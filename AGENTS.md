# Repository Guidelines

> **Read this before changing anything.** MacCV has a lot of coupled moving parts —
> a version recorded in five places, a generated header that is committed, two
> languages that must agree, three entry points that must build the app the same
> way. This file exists so that a change does not require being told twice.
>
> **The one command that answers "did I break something":**
>
> ```bash
> Scripts/verify.sh          # 24 stages, ~3 min, same command CI runs
> ```

## 1. What this project is

A macOS menu-bar clipboard manager. A Rust engine (`maccv-core`) linked as a
**static library** into a SwiftUI app, over a C ABI (`maccv-ffi`). No IPC, no helper
process — that decision is what makes a pasteboard read microseconds rather than
milliseconds, and most other choices follow from it.

The three commitments, which are also the things a change must not weaken:
**fast** (0.53 µs change detection), **light** (1.9 MB, idle costs nothing),
**private** (content never persisted, never leaves the machine).

## 2. Layout

```
crates/maccv-core/src/
  pasteboard.rs      NSPasteboard read/write, snapshots, watching  (the core)
  content.rs         typed views, classification
  redaction.rs       sensitive-content detection and masking
  secure_input.rs    synthetic keystrokes (paste without the clipboard)
  updater.rs         update check, verification, de-quarantining
  types.rs, error.rs
crates/maccv-core/tests/clipboard.rs    live tests against a private pasteboard
crates/maccv-core/examples/feed_check.rs  diagnostic: what the updater would pick

crates/maccv-ffi/src/
  lib.rs             the pasteboard C ABI, plus shared FFI plumbing
  updates.rs         secure input, redaction, updater C ABI
crates/maccv-ffi/include/maccv.h   GENERATED by cbindgen. Committed. Never edit.
crates/maccv-ffi/tests/smoke.c     the C smoke test

apps/mac/
  project.yml              SOURCE OF TRUTH for the Xcode project
  MacCV.xcodeproj          generated by xcodegen. Not committed.
  Sources/MacCV/           SwiftUI app + CRepresentationStorage + --self-test
  Resources/Localizable.xcstrings   en + zh-Hans, all UI strings

docs/                      the website (GitHub Pages) AND the standards
  index.html, zh/index.html   bilingual site
  SECURITY.md, PERFORMANCE.md, TESTING.md, RELEASING.md
  src/, changelog/            redirect stubs the footer links to

Scripts/
  build-rust.sh        cross-compiles + lipos the engine (called by Xcode)
  build-app.sh         builds one architecture, asserts the slice. Called by CI,
                       verify.sh and the release workflow — one implementation.
  make-dmg.sh          packages a DMG, mounts it and runs the app inside
  bump-version.sh      updates every place the version appears, then verifies
  changelog-notes.sh   extracts release notes from CHANGELOG.md
  verify.sh            every check, in fail-fast order
  publish.sh           creates and configures the GitHub repository
  checks/*.py          individual invariant checks
  dmg/                 DMG background generator and dmgbuild settings

assets/                logo, social preview, README preview (SVG sources + PNGs)
```

**Where logic belongs.** A decision written in `maccv-ffi` usually belongs in
`maccv-core`, where it can be tested without a C caller. `maccv-ffi` translates; it
does not decide. Same for the Swift side: if a view contains a rule rather than a
layout, the rule belongs in `ClipboardStore` or `AppSettings`.

## 3. The coupled-files map

**This is the section that saves the most time.** Each row is a change and the files
it forces you to touch. Missing one of these is the usual cause of a red CI run or,
worse, a released inconsistency.

### 3.1 Changing the version

| File | What |
|---|---|
| `Cargo.toml` | `[workspace.package] version` — the authority |
| `apps/mac/project.yml` | `MARKETING_VERSION` **and** `CFBundleShortVersionString` **and** `CURRENT_PROJECT_VERSION` (build number) |
| `CHANGELOG.md` | `[Unreleased]` → `[X.Y.Z]`, plus the comparison links at the bottom |

**Do not edit these by hand.** Run `Scripts/bump-version.sh`, which updates all of
them and then asserts they agree:

```bash
Scripts/bump-version.sh --bump patch   # or minor, major, or an explicit version
Scripts/bump-version.sh --dry-run 0.2.0
```

`Scripts/checks/version_consistency.py` fails the build if they disagree. A version
that disagrees with itself only shows up *after* publishing, when auto-update has
already stopped working for everyone who installed.

### 3.2 Changing Rust code in `maccv-core`

| Also needed | Why |
|---|---|
| A test | See §5. Non-trivial fixes need a named regression test with a comment explaining the original failure. |
| `crates/maccv-core/src/lib.rs` re-exports | If a new public type is meant to be reachable from `maccv-ffi`. |
| `docs/PERFORMANCE.md` + the asserting test | If you change path cost. |

### 3.3 Adding or changing C ABI surface

| File | What |
|---|---|
| `crates/maccv-ffi/src/lib.rs` or `updates.rs` | The function. `#[unsafe(no_mangle)]`, doc comment stating ownership. |
| `Scripts/build-rust.sh` consumers | Nothing — but **rebuild** so the header regenerates. |
| `crates/maccv-ffi/include/maccv.h` | **Generated. Commit the regenerated version.** |
| `crates/maccv-ffi/cbindgen.toml` | If the type needs special handling (e.g. it leaks a Rust type into C). |
| `crates/maccv-ffi/tests/smoke.c` | A null-pointer test **and** a round-trip test. |
| `apps/mac/Sources/MacCV/ClipboardEngine.swift` | A Swift wrapper with the memory rules handled in one place. |

```bash
cargo build -p maccv-ffi            # regenerates include/maccv.h
Scripts/verify.sh --quick           # fails if the committed header is stale
```

**Header notes:**
- `crates/maccv-ffi/build.rs` watches the whole `crates/maccv-ffi/src/` directory. A narrower watch once left the
  header stale without warning — do not narrow it again.
- Use `*const c_char`, **not** `*const i8`. `c_char` emits `char *`, which accepts
  string literals; `i8` emits `int8_t *`, which needs a cast at every call site.
- Opaque handles must be declared by hand in `cbindgen.toml`'s `after_includes` and
  excluded via `[export] exclude`, or their Rust fields leak into the header. This
  already happened with `MaccvPasteboard` (`Pasteboard inner`).

### 3.4 Changing the Swift app

| Also needed | Why |
|---|---|
| `apps/mac/Resources/Localizable.xcstrings` | Every user-visible string, in `en` **and** `zh-Hans`. |
| A test in `SelfTest.swift` | If the change touches the engine boundary. |

`Scripts/checks/i18n.py` fails if a key used in code is absent from the catalog, or
if either language is missing a translation. A missing key renders as the key
itself, which is invisible in English and obvious in Chinese.

**Do not** add a stored property to `ClipboardStore`'s `@Observable` and expect
`deinit` to reach it — mark it `@ObservationIgnored`. `nonisolated` cannot be
applied to an observed stored property, and `nonisolated(unsafe)` on a *tracked* one
does not compile.

### 3.5 Changing settings

| File | What |
|---|---|
| `AppSettings.swift` | The property, plus its `Stored` field, plus `save()`/`apply()`. |
| `SettingsView.swift` | The control. |
| `Localizable.xcstrings` | Title **and** detail strings. |

`Scripts/checks/no_content_persistence.py` asserts `AppSettings.Stored` cannot hold a
clipboard type. Do not add `Data` or a `Clip*` field — that check will (correctly)
reject it.

### 3.6 Changing the update feed or the updater

| File | What |
|---|---|
| `Scripts/checks/write_feed.py` | The published shape. |
| `crates/maccv-core/src/updater.rs` | `ReleaseManifest` parsing. |
| `Scripts/checks/feeds.py` | Validation the engine enforces. |
| `.github/workflows/pages.yml` | Inputs, if a new field is needed. |
| `.github/workflows/release.yml` | The `package` step's outputs. |

**Every feed field must survive the engine's own validation** (`sha256` is 64 hex
chars, `download_url` is HTTPS, `size > 0`, architectures are unique). A field the
engine rejects means every installed copy silently stops updating.

### 3.7 Changing a workflow

| Also needed | Why |
|---|---|
| `.github/actionlint.yaml` | If you use a runner label actionlint does not know (`xcode-27`). |
| Same change in `verify.sh` | CI and `verify.sh` must run the same checks, or a green CI means nothing locally and vice versa. |
| Same change in `release.yml` | **Critical.** CI and release must build the app *identically*. They once did not — see §10.1. |

### 3.8 Changing the website

| Also needed | Why |
|---|---|
| `docs/zh/index.html` | Keep the structure identical; `website.py` compares section ids, anchors, table and list counts. |
| `docs/index.html` anchors | Section ids must match, or the language switch lands in the wrong place. |
| Version in the footer | Both pages. |

### 3.9 Changing a README

| Also needed | Why |
|---|---|
| The other README | `readme_parity.py` checks shared facts: the numbers, the limitation statement, doc links, the centred badge block, and equal section counts. Prose may differ; **facts may not**. |
| `docs/PERFORMANCE.md` | If you change a published number, the asserting test and the document both. |

### 3.10 Changing the brand or preview images

| Source | Outputs |
|---|---|
| `assets/logo.svg` | `assets/logo.png`, `assets/AppIcon.iconset/*` (8 sizes), `apps/mac/Resources/AppIcon.icns`, `docs/logo.png` |
| `assets/social-preview.svg` | `assets/social-preview.png`, `docs/social-preview.png` |
| `assets/preview-placeholder.png` | Generated by the script embedded in its commit; replace with `assets/preview.gif` and update both READMEs |

```bash
rsvg-convert -w 1024 -h 1024 assets/logo.svg -o assets/logo.png
```

### 3.11 Adding a dependency

| Check | Why |
|---|---|
| Not in `FORBIDDEN_CRATES` | `no_undeclared_network.py` blocks telemetry, analytics and AI SDKs. |
| `no_undeclared_network.py` passes | It also flags dynamic `Command::new(var)`. |
| Consider whether you need it | The engine shells out to system tools (`curl`, `shasum`, `ditto`, `hdiutil`, `spctl`, `xattr`) rather than pulling crates. That is a deliberate trade, not an oversight. |

## 4. Build, test, verify

```bash
Scripts/verify.sh                # everything: 24 stages, ~3 min
Scripts/verify.sh --quick        # skip the app build (Rust + checks only)
Scripts/verify.sh --no-network   # skip the one check that reaches out

cargo test --workspace                     # engine tests
cargo test -p maccv-core -- --nocapture    # see timings
Scripts/build-app.sh --arch arm64 --out /tmp/app   # one architecture, slice asserted
```

**`Scripts/verify.sh` is the contract.** CI runs the same stages. If it passes
locally it should pass in CI; if that stops being true, the stages have drifted and
that is the bug.

The app can verify itself end to end:

```bash
"dist/arm64/MacCV.app/Contents/MacOS/MacCV" --self-test
```

It runs against a **process-private** pasteboard, so it never reads or clobbers your
real clipboard, and CI does not depend on what happens to be copied.

## 5. Invariants you must not break

These are enforced by `Scripts/checks/`. Read them before arguing with them.

| Invariant | Enforced by | Meaning |
|---|---|---|
| **No data leaves the machine** | `no_undeclared_network.py` | No process spawn outside the allowlist, no host outside the documented set, no analytics/AI dependency. |
| **Clipboard content is never persisted** | `no_content_persistence.py` | History is in memory. `AppSettings.Stored` cannot hold a clipboard type. |
| **No AI reads user data** | `no_undeclared_network.py` | No model, local or remote. This must stay true. |
| **The C ABI never traps** | `maccv-ffi` tests + `smoke.c` | Every pointer validated; null returns a status, never dereferences. |
| **Clipboard content is untrusted** | `redaction.rs` tests | Hostile input cannot panic a detector or truncate a value. |
| **A verified update is never de-quarantined before verification** | `updater.rs` tests | Order is the control: hash → signature → *then* clear the flag. |
| **Performance claims are asserted** | `PERFORMANCE.md` + tests | A published number has a test that fails if it regresses. |
| **The two languages agree** | `i18n.py`, `readme_parity.py`, `website.py` | On keys, facts and structure — not prose. |
| **This guide stays true** | `agents_doc.py` | Every path, script and stage count in `AGENTS.md` resolves. |
| **Workflows pass what scripts read** | `workflow_env.py` | The env names a workflow sets match what its script requires. An `ARM_URL`/`ARM64_URL` mismatch once shipped a release that never wrote its update feed. |
| **Build inputs are committed** | `tracked_files.py` | No file the build reads is excluded by `.gitignore`. An ignored `Info.plist` built locally and failed in a fresh clone. |

### Two rules when adding a check

1. **Verify the check catches a violation.** A check that has never failed is not
   known to work. Every existing check was validated by deliberately introducing the
   violation — the persistence check was confirmed by adding a
   `lastSnapshot: ClipSnapshot?` field, watching it fail, then removing it.
2. **Do not allowlist your way out.** Test fixtures that trip a scanner get *changed*,
   never exempted — an exemption also disables the check for future code. This has
   happened once already; see §10.2.

## 6. Platform constraints

Hard limits. If a task seems to require violating one, the task is wrong.

### 6.1 macOS: the pasteboard is world-readable

Content on the system pasteboard can be read by any application. **There is no API to
write to it privately.** `NSPasteboardContentsOptionsCurrentHostOnly` restricts device
sync, not other apps. AppKit has no `concealed` flag —
`org.nspasteboard.ConcealedType` is a voluntary convention.
`NSPasteboardAccessBehavior` governs only *this* process's reads.

The one mechanism that genuinely denies other apps access is
`secure_input.rs`: synthetic keystrokes, so the content never enters a shared channel.
It needs Accessibility permission, is slower, and is text-only — which is why it is
opt-in.

**Never write documentation claiming MacCV prevents other apps from reading the
clipboard.** Say what it does and name the limit.

### 6.2 `objc2` does not implement `Send` for `NSObject` subclasses

Do not `unsafe impl` around it. The watcher reopens the pasteboard by name inside its
own thread; only `Send` data crosses the boundary.

### 6.3 Threading

All AppKit types used here are "any thread" in `objc2`, and the methods used are
documented as usable off the main thread. `NSImage` is decoded for metadata only,
never rasterised, which keeps it off the main-thread-only rendering paths.

### 6.4 macOS 15.4-only APIs

`-[NSPasteboard accessBehavior]` is `API_AVAILABLE(macos(15.4))`. On 15.0–15.3 the
selector **does not exist**, and messaging it is undefined behaviour, not a clean
failure. Probe with `respondsToSelector` and handle `AccessBehavior::Unavailable`
(distinct from `Default` — "not policed" and "cannot tell" lead to different UI).

### 6.5 Universal builds

Use `-destination 'generic/platform=macOS'`. The usual `platform=macOS` **silently
narrows ARCHS to the host**, while `showBuildSettings` still reports
`arm64 x86_64`. Always verify with `lipo -info` on the product; the settings are not
evidence. `Scripts/build-app.sh` does this assertion for you.

### 6.6 Gatekeeper will warn, and `xattr` will not fix it

The release is ad-hoc signed until a Developer ID exists, so macOS shows *"Apple could
not verify MacCV.app is free of malware"*. Two things are commonly suggested and both
fail:

- `xattr -d com.apple.quarantine MacCV.app` — the attribute is set **per file**, so
  clearing only the bundle leaves it on the executable, the `.icns` and the
  localisations. `-dr` clears them, and…
- …`spctl --assess --type execute` **still rejects it**, because Gatekeeper's verdict
  is about the signature, not the flag. `Signature=adhoc`, `TeamIdentifier=not set`.

The only fix is a Developer ID certificate plus notarization. `release.yml` does that
when `MACCV_DEVELOPER_ID` is set, and `docs/RELEASING.md` documents it. Do not present
`xattr` as a solution.

### 6.7 Sandboxing

The app is **not** sandboxed, and that is deliberate: it must read the pasteboard, and
the sandbox would not change what it can see.

## 7. Coding conventions

### Rust

- `cargo fmt` decides formatting. Do not argue with it.
- `missing_docs` is denied. Public items need doc comments.
- `unsafe_op_in_unsafe_fn` is denied. Every `unsafe` block needs a `// SAFETY:`
  comment saying why it is sound.
- Release uses `panic = "abort"`. Prefer `Result`; a panic is a crash.
- Snake case files, Pascal case types.
- Tests are named as sentences describing the guarantee:
  `writes_files_as_file_urls`, `change_count_is_cheap_enough_to_poll`,
  `freeing_a_result_with_empty_optional_fields_does_not_crash`.

### Swift

- Swift 6, strict concurrency. UI state on the main actor.
- Objective-C objects must not cross threads.
- **C pointers must never point at a Swift `Data`'s transient storage.**
  `withUnsafeBytes` lends a pointer only for its closure. `CRepresentationStorage`
  copies payloads into C-owned allocations; use it rather than passing `Data` buffers.
- Any owning string from the engine is freed through `free_owned`, which skips the
  static `EMPTY` sentinel. Comparing against a `const`-held `c""` literal is **not**
  reliable — see §10.3.

### Comments

Explain **why**, not what. The bar: a comment earns its place if it records a decision,
a platform constraint, or a failure that would otherwise be rediscovered. Comments
that restate the code should be deleted.

### Tests

- New engine behaviour needs a test.
- Live tests use `Pasteboard::unique()` via the `scratch()` helper — **never the
  developer's clipboard.**
- Assert documented performance claims rather than measuring by hand.
- No binary fixtures; the 1×1 PNG is written out as bytes so a reader can see what is
  asserted.
- No network in tests. The update test points at `127.0.0.1:9`, which cannot listen.

## 8. Documentation rules

| Document | Owns |
|---|---|
| `AGENTS.md` (this file) | How to change the project without being told twice |
| `CONTRIBUTING.md` | The same, for human contributors — keep the two consistent |
| `docs/SECURITY.md` | Invariants, what macOS makes impossible, the plugin model |
| `docs/PERFORMANCE.md` | Budgets and how each number is measured |
| `docs/TESTING.md` | What is tested and **what is not**, and why |
| `docs/RELEASING.md` | Channels, the release procedure, emergency revocation |
| `README.md` / `README.zh-CN.md` | For someone deciding whether to install this |

Rules:

1. **Separate what is enforced from what is a limit.** "Enforced" means a check
   fails without it. "Platform limit" means nothing can change it. Never blur them.
2. **Record what is not done.** `TESTING.md` §T3 lists untested areas as decisions,
   not gaps. An unmeasured claim is one somebody will overstate.
3. **A number in a document needs a test.** Otherwise it is stale within a month.
4. **Changing a rule means changing its enforcement in the same commit.** A document
   that describes a check which no longer exists is worse than no document.

## 9. Releasing

Full detail in `docs/RELEASING.md`. The short version:

```bash
Scripts/bump-version.sh --bump minor
# move [Unreleased] notes into the new version's section
Scripts/verify.sh
git commit -am 'chore(release): 0.2.0' && git push origin main
git tag -a v0.2.0 -m 'MacCV 0.2.0' && git push origin v0.2.0
```

- **The tag is the only trigger.** Nothing publishes from a branch, so what ships is
  exactly what was tagged and verified.
- **A hyphen selects the preview channel.** `v0.2.0-rc.1` → `docs/preview.json` and a
  GitHub pre-release. Plain `v0.2.0` → `docs/latest.json`. Users on stable never see a
  preview.
- **A public release must have run as a preview first.** The only exception is the
  emergency path.
- **Two DMGs, one per architecture**, plus `SHA256SUMS`. A universal image would be
  roughly twice the size for every user. The feed carries per-architecture entries, so
  an Intel Mac does not fetch an Apple-silicon build.
- **A tag rebuilds from scratch.** It does not reuse CI artifacts — that would break
  provenance. This is safe *because* CI and release call the same
  `Scripts/build-app.sh`.
- **Emergency:** add the bad version to the feed's `revoked` array. It accumulates, so
  it never needs re-adding. A revoked build shows a window with no close button; it
  does not kill the process and does not update silently.

## 10. Gotchas that have already bitten

Each of these cost real time. They are recorded so they cost it once.

### 10.1 CI and release built the app differently

CI used `-destination 'platform=macOS'` (host architecture only) and never touched the
DMG path. The release used `generic/platform=macOS` with `ARCHS` pinned and ran
`make-dmg.sh`. So **the packaging path — background generation, dmgbuild, tiffutil,
icon layout, mounting — ran for the first time on release day**, and CI's green tick
validated a build shape that was never shipped.

Fixed by `Scripts/build-app.sh`: one implementation, called by `verify.sh`, CI and the
release workflow. **Keep it that way.** If you need a build flag changed, change it in
the script.

### 10.2 GitHub push protection flagged a test fixture

A redaction test used a literal that looked like a Stripe key. The correct response was
to change the fixture — **not** to click "allow", which would also disable the check
for every future commit.

The fix has two real bounds, both now asserted:

- **≥ 16 characters**, the detector's `MIN_BODY`. An 11-character placeholder made the
  test *pass while detecting nothing* — worse than no test.
- **< 24 characters**, where prefix + body reaches the shape scanners look for.
  `TESTFIXTUREONLY0000000000000000` looked reassuringly fake and was flagged anyway.

The secret was in an unpushed commit, so `git filter-branch` was used. Note
`--tree-filter` reports success even when a `sed` had no effect — verify by reading
the content back, not by trusting the exit code.

### 10.3 `free()` on static memory

`MaccvString::EMPTY` held `c"".as_ptr()` inside a `const`. A `const` is instantiated
per codegen unit, so the address stored in a struct field did **not** compare equal to
the same const read elsewhere. The guard failed, `free()` was handed read-only static
memory, and the process died with SIGBUS on **every failed update check** — the most
common path.

The sentinel now points at a `static [u8; 1]`, which has one address crate-wide.
`free_owned` is the only way to release an owned string.

### 10.4 `getxattr` with a one-byte buffer

`has_quarantine` probed with a 1-byte buffer. A real quarantine value is ~20 bytes, so
`getxattr` returned `-1 / ERANGE` — indistinguishable from "attribute absent" if you
only check the sign. Detection never fired for the thing the updater exists to detect.

Pass a null buffer with size 0 to query the length. That is the only reliable
existence test.

### 10.5 Byte-offset slicing on multi-byte text

Four detectors in `redaction.rs` walked bytes while slicing with `&text[i..i+n]`,
which panics inside any CJK character. They now walk `char`s and convert to byte ranges
once. **If you write a scanner, walk characters.**

### 10.6 cbindgen watched only one file

Adding `crates/maccv-ffi/src/updates.rs` regenerated nothing, so the committed header silently
disagreed with the library — and the mismatch only appeared at link time in a C
caller. `crates/maccv-ffi/build.rs` now watches the whole `crates/maccv-ffi/src/` directory.

### 10.7 `dmgbuild` ignored the app

`dmg-settings.py` had `files = []` and never added the bundle, so the first image
contained a background and an Applications symlink and nothing else. It now refuses to
build without the bundle rather than silently producing an empty image. `make-dmg.sh`
also verifies by **mounting the image and running the app inside it** — because
"the DMG was created" is not the same as "the DMG works".

### 10.8 The C smoke test linked the wrong library

With both a `.a` and a `.dylib` present, the linker prefers the dylib — so the smoke
test exercised a different artifact from the one the app links, and needed a runtime
search path to run. `verify.sh` now names `libmaccv_ffi.a` explicitly.

### 10.9 Topics were one 102-character string

`${TOPICS[*]// /,}` joined twelve topics into one string; the API rejects anything over
50 characters. `gh repo edit` takes one `--add-topic` per topic.

### 10.10 `gh repo create` was blocked by the safety classifier

Creating a public repository is outward-facing and was correctly refused. Publishing is
`Scripts/publish.sh`, run deliberately. Two things it cannot do, because GitHub exposes
no API for them: the social preview image and a custom domain.

## 11. Commit and pull request conventions

[Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`,
`perf:`, `refactor:`, `docs:`, `test:`, `build:`, `ci:`, `chore:`, with scopes where
useful (`feat(app):`, `docs(ffi):`).

A PR says **what changed, why, and how to verify it**. If it changes behaviour, add a
`CHANGELOG.md` entry under `[Unreleased]` — release notes are generated from that file.
Keep one concern per PR.

Before opening one:

```bash
Scripts/verify.sh
```

## 12. When in doubt

- **`Scripts/verify.sh`** answers "did I break something".
- **§3** answers "what else do I have to touch".
- **`docs/TESTING.md` §T3** answers "is this actually tested" — check before assuming.
- If an invariant in §5 seems wrong, change the invariant, the document and the check
  **in the same commit**, and say why. Do not weaken the check alone.
