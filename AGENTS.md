# Repository Guidelines

MacCV is a macOS clipboard manager: a Rust engine (`maccv-core`), a thin C ABI
(`maccv-ffi`), and a SwiftUI front end.

## Project Structure & Module Organization

| Path | Contents |
|---|---|
| `crates/maccv-core/src/` | The engine: `pasteboard.rs`, `content.rs`, `redaction.rs`, `secure_input.rs`, `updater.rs`. Plain Rust, directly testable. |
| `crates/maccv-core/tests/clipboard.rs` | Live tests against a process-private pasteboard. |
| `crates/maccv-ffi/src/` | The C ABI surface. Translates only — puts no decisions here. |
| `crates/maccv-ffi/include/maccv.h` | Generated by cbindgen. Never edit by hand. |
| `apps/mac/Sources/MacCV/` | SwiftUI app. `project.yml` is the source of truth; `MacCV.xcodeproj` is generated and uncommitted. |
| `Scripts/` | `build-rust.sh` (shared by Xcode pre-build and CI), `publish.sh`, `changelog-notes.sh`. |
| `assets/`, `docs/` | Logo/social SVGs (PNGs rendered from them) and the GitHub Pages site. |

Keep logic in `maccv-core`. A decision in `maccv-ffi` almost always belongs one
layer down, where it can be tested without a C caller.
## Build, Test, and Development Commands

```bash
cargo test --workspace            # run the engine tests
cargo fmt --all --check           # formatting gate
cargo clippy --workspace --all-targets -- -D warnings
cd apps/mac && xcodegen generate  # regenerate the Xcode project from project.yml
Scripts/build-rust.sh --profile release --arch universal
```

To prove every layer connects (Rust → C ABI → Swift), run the C smoke test:

```bash
cargo build --release -p maccv-ffi
clang -std=c11 -Wall -Wextra -Werror -I crates/maccv-ffi/include \
  crates/maccv-ffi/tests/smoke.c -o /tmp/maccv_smoke \
  -L target/release -lmaccv_ffi -framework AppKit -framework Foundation
/tmp/maccv_smoke
```

## Coding Style & Naming Conventions

- **Rust**: `cargo fmt` decides formatting; do not argue with it in review. Public
  items need doc comments (`missing_docs` is denied), and every `unsafe` block
  needs a `// SAFETY:` comment. Prefer `Result` over panicking — release builds use
  `panic = "abort"`. `snake_case` files/functions, `PascalCase` types.
- **Swift**: Swift 6 with strict concurrency; keep UI state on the main actor.
  Objective-C objects must never cross threads, and C pointers must never point at
  a Swift `Data`'s transient storage — see `CRepresentationStorage`.

## Testing Guidelines

- New engine behaviour requires a test. Extend
  `crates/maccv-core/tests/clipboard.rs`, exercising the real framework — against
  a process-private pasteboard, never the developer's clipboard — then clean up.
- Name tests as full sentences describing the guarantee, e.g.
  `writes_files_as_file_urls`, `change_count_is_cheap_enough_to_poll`.
- Assert documented performance claims in a test rather than measuring by hand.
- FFI additions must pass the C smoke test.

## Commit & Pull Request Guidelines

Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
`feat:`, `fix:`, `perf:`, `refactor:`, `docs:`, `test:`, `build:`, `ci:`, `chore:`.
Scopes are used where useful (`feat(app):`, `docs(ffi):`).

Pull requests should say what changed, why, and how to verify it, and include the
checklist from `.github/PULL_REQUEST_TEMPLATE.md`. Link issues with `Closes #N`,
and keep one concern per PR. User-visible changes need a `CHANGELOG.md` entry under
`[Unreleased]` — release notes are generated from that file.
